# Governance

FeastCloud uses an open technical roadmap with safety-critical maintainership.

- Maintainers accept changes based on product fit, correctness, security, accessibility, license compatibility, and operational evidence.
- Public contract changes require an architecture decision record and compatibility review.
- Country or language packs may be community-maintained, but “certified” status requires documented native/operator review.
- A connector can be removed from the default distribution if its upstream terms become incompatible or its security posture is unacceptable.
- The project will publish release provenance, dependency inventory, and reproducible migration guidance.

The initial maintainership model is benevolent maintainer. A multi-stakeholder technical steering process should be established before version 1.0.
